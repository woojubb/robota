A project session store given `deletion` (the `checkpoints` state facet, a subagent log remover and the log sinks to tell) removes everything a deleted session left: its log, payloads, checkpoints and subagent logs, and its record last, so a delete that stops part-way keeps the session listed and deleting it again finishes it. A checkpoint writer holding the session's lease refuses the delete (`ProjectSessionDeletionStoppedError`, reason `checkpoint-writer`) with no checkpoint touched, a directory still `partial` after a bounded number of retries stops it (`incomplete-removal`), and a host that cannot remove directories is refused before anything is touched; without `deletion` a delete removes only the record, as before. The claim markers' lock file stays by design. `removeSubagentLogs(baseLogsDir, parentSessionId)` removes one parent's `subagents/` directory on every platform, following no link and refusing an id that is not a session id or a parent or `subagents/` entry that is a link or not a directory. The mutation boundary's `append` (and the state facet's `appendText`) takes `{ create: false }`, which creates nothing and answers `false` when the file or a directory on the way is missing, and now returns whether it appended; a host boundary must return it. `WorkspaceSessionLogSink` creates a session's log only with its first line, so a line flushed after the session was deleted, by this process or another, creates nothing and is dropped quietly, and it drops every line and payload of an id a store tells it was deleted until that id is claimed again.
