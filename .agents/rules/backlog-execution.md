# Backlog Execution

Parent: [AGENTS.md](../../AGENTS.md)

## Prospective work

One issue, accepted specification, or direct request owns the work. Entry and Completion boundaries are defined in [spec-workflow.md](spec-workflow.md). The responsible author may delegate useful implementation or expert review, but no fixed triager/reviewer/scenario/writing chain is required.

Real user-visible changes still need an applicable scenario. The author decides applicability directly and records a concise N/A reason when no user behavior changed.

Commit coherent implementation units. Never require planning-only, continuation-only, receipt-only, closeout-only, or file-move-only commits solely for process progression.

## Findings

Classify actionable findings by impact and cause, fix in-scope defects, and record out-of-scope root causes on an existing authoritative issue when possible. One independent final review is required; repeated clean reviews are not. Review meaningful repair deltas after findings.

## Historical records

Existing Task/spec records retain their historical evidence as read-only project history. They do not keep
the retired lifecycle executable, and unfinished work resumes through the current entry and completion
boundaries.
